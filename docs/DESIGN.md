# MALBIT product design north star

## 무엇을 만드는가

MALBIT는 일본어 설명을 우선 제공하는 한국어 완전 초보자가 게임과 이야기를 따라가며
한국어를 익히고, 이후 TOPIK I·II 실전 학습까지 자연스럽게 확장하는 모바일 우선 학습
PWA다.

장기적으로는 서울을 돌아다니며 한국어를 실제 상황처럼 사용하는 학습 RPG로 확장한다.
학습이 게임을 방해하는 시험지가 아니라, 새로운 장소·퀘스트·캐릭터 보상을 여는 행동이
되어야 한다.

## 첫 핵심 사용자

- 한국어를 거의 읽지 못하는 완전 초보자
- 첫 설명 언어는 일본어
- 시험 점수만이 아니라 재미와 짧은 성취 때문에 다시 방문하는 사용자

## 첫 10분 약속

사용자는 긴 설정이나 레벨 검사 없이 게임·여행모드 첫 단계를 끝낸다. 그 과정에서 적어도
하나의 한국어 표현을 보고, 듣고, 선택하고, 성공 보상과 다음 목표를 이해한다.

## 제품 우선순위

1. 재미·재방문·시장 경쟁력
2. 정답·해설·번역의 정확성
3. 실제 모바일 화면·터치 조작 품질
4. 초보에서 TOPIK 실전으로 이어지는 확장성
5. 혼자 운영해도 검수·배포·되돌리기가 가능한 단순한 구조

정확성은 다른 항목과 교환하지 않는다. 재미있는 오답 제조기는 학습 앱이 아니라 화려한
거짓말 기계다.

## 핵심 경험

- 게임 아래 독립된 Travel Mode와 Wordlight Expedition
- 짧게 반복하는 Shorts와 Random Practice
- 틀린 문제와 단어를 다시 만나게 하는 Review·Vocabulary
- 실제 시험을 준비하는 전체 모의고사
- 일본어 초보 설명, 자연스러운 한국어 듣기, 읽기·쓰기·말하기로 확장 가능한 구조

## 서울 학습 RPG 방향

서울맵은 장식용 메뉴가 아니라 학습과 재방문을 연결하는 장기 메타게임이다.

1. 사용자가 오늘의 5~10분 학습 미션을 완료한다.
2. 서울의 장소 또는 NPC 퀘스트가 열린다.
3. 편의점·지하철·카페·관광지 같은 상황에서 배운 표현을 다시 사용한다.
4. 정답과 복습으로 재화·의상 조각·지역 평판을 얻는다.
5. 아바타를 꾸미거나 다음 장소를 열고, 다음 날 이어지는 퀘스트를 확인한다.

지도는 처음부터 서울 전체를 만들지 않는다. 한 개 지역, 짧은 이동, NPC 3명 이하,
학습 퀘스트 하나, 무료 꾸미기 보상 하나로 vertical slice를 먼저 검증한다. 이 작은 구간에서
첫 퀘스트 완료율과 다음 날 재방문이 오르지 않으면 도시 규모를 늘리지 않는다.

현재 첫 vertical slice는 **인천공항 제1터미널 → 서울역 환승 → 명동역**이다. 사용자는
완전 초보 한국어 6문제를 풀어 게임 재화인 `여행 원`을 얻고, 가격·시간·남은 재화를
비교해 공항철도 일반열차, 직통열차, 인터내셔널 택시 중 이동 수단을 고른다. 실제 운임,
소요 시간, 승차 위치는 공항철도·인천공항·서울시 공식 자료에 근거하고 변경될 수 있는
정보는 앱에서 출발 전 재확인을 안내한다.

선택은 칭호만 바꾸지 않는다. 지갑 잔액, 여행 시각, 이동 장면과 다음 지역에서 쓸 자원이
달라진다. 정답을 많이 맞히면 더 빠른 이동 수단이 열리고, 저렴한 길을 택하면 다음 지역의
수집·경험에 쓸 재화가 더 남는다. 기기 시각에서 시작한 게임 시간이 이동과 문제 풀이에 따라
흐르며, 이후 지역은 낮·밤과 요일 이벤트를 데이터로 확장한다.

모든 Travel Mode 장면 그래픽은 같은 캐릭터와 팔레트를 유지한 생성형 귀여운 도트 그래픽을
사용한다. 배경에는 플레이어·NPC·아이템을 구워 넣지 않고, `배경 / 플레이어 스킨 / NPC /
상호작용 소품·보상 / UI 타일`을 투명한 독립 에셋과 DOM 레이어로 합성한다. 플레이어 레이어만
교체해도 어떤 장소에서든 같은 아바타 커스터마이징이 유지되어야 한다. 여행 장면·선택지·보상
표시는 이모티콘이나 임시 범용 아이콘으로 대신하지 않고 동일 콘셉트로 생성한 소품과 재사용
가능한 UI 타일을 쓴다. 단, 번역·접근성·터치 품질을 위해 글자는 이미지에 굽지 않고 HTML로
올린다.

학습 입력은 `문제 → 채점`으로 끝내지 않는다. `현장 상황 → 말하기·표지 터치·기계 조작 같은
행동 → 장면 속 즉시 반응 → 재화·수집품 또는 회복 가능한 시간 손실` 순서로 완결한다. 같은
4지선다여도 행동의 외형과 결과가 달라야 하며, 정답은 다음 선택을 실제로 열어야 한다.

### Travel UI 그래픽·레이아웃 합격 규칙

- 가변 높이 카드에 정사각형 프레임 이미지를 `background-size: 100% 100%`로 늘리지 않는다.
  모서리가 찌그러지고 내부 안전 여백이 사라지므로 9-slice `border-image`와 별도 내용 래퍼를 쓴다.
- 모든 Travel 컨테이너와 자식은 `box-sizing: border-box`, `min-width: 0`, `max-width: 100%`를
  기본 계약으로 삼는다. 긴 일본어·한국어는 줄바꿈하고 핵심 설명을 말줄임표나 고정 높이로 자르지 않는다.
- 배경만 비율 고정 영역으로 두며, 텍스트·보상·가방·버튼은 절대 위치에 놓지 않는다. 장식 레이어만
  잘릴 수 있고 학습 내용과 조작 대상은 부모 안전 영역 안에 완전히 들어와야 한다.
- UI·소품·NPC 이미지는 장면과 분리하고 텍스트를 굽지 않는다. 이미지가 늦게 로드되거나 번역 길이가
  달라져도 레이아웃 순서와 터치 영역이 바뀌지 않아야 한다.
- 병합 전 일본어 기준 320·375·390·430px에서 가로 돌출, 직접 자식 겹침, 44px 미만 터치 영역,
  콘솔 오류를 자동 검사하고 주요 시작·정답·보상·복귀 화면을 눈으로 확인한다. 하나라도 실패하면
  “대부분 괜찮다”로 통과시키지 않는다.
- 이 규칙은 새 화면만의 장식 지침이 아니라 Travel Mode 전체의 회귀 방지 계약이다. UI 변경 작업은
  같은 검사를 확장하고, 기존 단어장·게임·복습·여행 저장 루트 전후 비교까지 통과해야 한다.

### 상위권 모바일 도트 RPG 품질 기준

- 벤치마크의 에셋이나 화면을 복제하지 않고 수동 탐험의 반응성, 깊이 있는 레이어, 세로 화면의
  정보 절제 같은 제품 원리만 가져온다. 서울 고유의 현대적 장소와 한국어 학습 행동이 정체성이다.
- 한 칸 이동마다 탐험 DOM 전체를 갈아 끼우지 않는다. 플레이어는 일정 속도로 보간하고 카메라는
  조금 늦게 따라오며, 연타 입력은 순서를 보존한다. 막힌 길·포털·조사에는 서로 다른 짧은 반응을 준다.
- 최종 캐릭터 규격은 4방향 idle/walk, 일관된 발 접지점, 그림자, 전경 가림 순서를 포함한다.
  임시 상하 흔들기만으로 완성된 걷기 애니메이션이라고 부르지 않는다.
- 탐험 화면은 맵이 가장 큰 면적을 차지하고 목표·재화·조사는 최소 HUD 계층으로 올린다. 학습
  설명이 열릴 때만 읽기 쉬운 카드가 확장되며, 평상시에는 큰 문서 카드가 이동 화면을 밀어내지 않는다.
- 배경, 충돌, 전경, 캐릭터, NPC, 상호작용, 조명·날씨 효과를 독립 레이어로 합성한다. 한 장의
  완성 그림에 캐릭터나 효과를 굽거나 검은 반투명 도색으로 밤을 흉내 내지 않는다.
- 실제 모바일에서 이동 시작·중간·도착 좌표와 카메라 애니메이션, 연타 큐, 재진입, 콘솔 오류를
  측정한다. 정지 화면만 예쁘거나 CSS에 transition 문자열만 있는 상태는 합격하지 않는다.

### 전체 UI 시각 계약

- 화면마다 임의의 간격·모서리·글자·색을 만들지 않고 `styles.css`의 의미 기반 UI 토큰을 사용한다.
  새 값이 필요하면 한 화면에 숫자를 박기 전에 토큰과 재사용 컴포넌트의 책임부터 확장한다.
- 최소 본문·보조 글자 크기, 44px 터치 영역, 좌우 대칭, 중앙 오차, 다국어 줄바꿈과 명암을
  실제 320·375·390·430px DOM 기하와 밝은/어두운 테마 화면 증거로 검사한다.
- 밝은 테마와 어두운 테마는 모두 제품 기능이다. “어두운 임시 타일 금지”를 “전 화면 강제 밝게”로
  해석하지 않는다. 밝은 테마는 밝은 표면, 어두운 테마는 충분한 대비의 남색 표면을 쓰며,
  장면 그림을 검은 반투명 레이어로 임의 도색하지 않는다.
- Game Mode는 첫 기준 화면이다. 장비·등급·스테이지·지도 노드를 의미 없는 거의 검은 임시 카드로
  칠하지 않고 테마 표면과 명확한 선택·완료·위험 상태를 사용한다.
- Home은 두 번째 기준 화면이다. 첫 학습·빠른 연습·전체 모의·말하기·주간 목표 진입 카드를
  같은 밝은 표면, 간격, 44px 조작부, 10px 이상 보조문구로 통일하고 색은 기능 구분용 강조에만 쓴다.
- Shorts는 세 번째 기준 화면이다. 문제·선택·채점·강사형 해설을 밝은 공통 표면과 명확한
  선택·정답·오답 상태로 구분하고, 제출 전과 제출 후를 모두 네 가지 모바일 폭에서 검사한다.
- Random Practice는 네 번째 기준 화면이다. TOPIK I·II의 서로 다른 엔진을 같은 문제·선택·채점·
  번역·유형별 해설 위계로 묶고, 제출 전과 채점 후 열린 해설을 모두 네 가지 모바일 폭에서 검사한다.
- Review는 다섯 번째 기준 화면이다. TOPIK I·II 급수 필터, 오답 목록, 재도전, 요청형 전체 번역,
  채점과 선택지별 소거 해설을 같은 밝은 위계로 묶고, 해결 처리와 목록 재진입까지 네 폭에서 검사한다.
- Travel은 저장된 테마를 강제로 덮어쓰지 않는다. 월드→지역→구역→충돌 타일→조사·이벤트→포털
  순서의 데이터 구조를 유지하고, 캐릭터와 NPC를 배경에 굽지 않은 채 서울을 한 구역씩 확장한다.
- 호환 레이어의 과거 `!important`를 이기기 위한 예외는 한 곳의 고정된 bridge로 격리하고 개수를
  테스트한다. 새 UI 작업이 호환 레이어마다 CSS를 덧붙이는 방식으로 돌아가면 병합하지 않는다.
- 스크린샷 차이만으로 미적 품질을 판단하지 않는다. 자동 검사는 돌출·비대칭·작은 글자·어두운
  타일 같은 객관적 퇴행을 막고, 주요 화면은 병합 전에 사람이 직접 보아 의도된 위계와 조화를 확인한다.

### 학습 게임의 대화·채점·해설 합격 규칙

- 답을 제출하기 전 선택지에는 한국어만 표시한다. 설명 언어 번역은 채점 뒤 사용자가 고른 보기와
  정답에만 공개한다. 문제 화면에서 번역이 답을 미리 알려 주면 학습도 게임도 성립하지 않는다.
- NPC 퀘스트는 한 문장 안내 뒤 문제로 끊지 않고, 최소 3턴의 상황 대화를 거쳐 NPC의 마지막 말에
  실제로 답하거나 행동하게 만든다. 대화문과 번역은 한 턴씩 공개해 장면의 리듬을 유지한다.
- 자유 작문은 단어·조사·어미를 분리한 충분한 말뭉치를 제공한다. 모범 문장은 큰 보상, 검증된 자연스러운
  대체 문장은 제한된 작은 보상, 뜻이 성립하지 않는 조합은 보상 없이 구체적인 재시도 단서를 준다.
- 해설은 `정답 근거 → 고른 보기/함정 분석 → 다음 문제에 재사용할 풀이 요령`의 세 단계로 쓴다.
  “정답입니다”나 정답 문장 재진술만으로 끝내지 않는다.
- Game Mode는 채점·렌더링 때 `scrollIntoView`나 강제 smooth scroll을 호출하지 않는다. 사용자가 보던
  위치를 유지하고, 필요한 피드백은 현재 흐름 안에서 자연스럽게 확장한다.
- 위 규칙은 문자열 존재 검사로 끝내지 않는다. 일본어 모바일 화면에서 제출 전 번역 0개, 제출 뒤
  선택/정답 번역만 노출, 대화 턴 진행, 대체 문장 보상, 카드 containment, 스크롤 위치를 회귀 검사한다.

화면 이름과 진행 경험은 Travel Mode로 유지하되 기존 `malbitStoryV1` 저장 키와 이전 episode
객체를 삭제하지 않아 업데이트 전 단어장·게임·여행 기록을 잃지 않는다.

탐험은 제품의 본체가 아니라 공부를 지속시키는 보상 장치다. 문제를 풀지 않고 지도만
소비하거나, 지도 때문에 정답·해설·복습이 약해지는 구조는 만들지 않는다.

## 아바타·결제 보류 원칙

아바타는 현재 학습 성취를 눈에 보이게 만드는 **보상 장치**다. 수익화 장치가 아니다.

- 모든 기본 의상, 지역 기념품, 색상 변형, 헤어, 액세서리, 감정표현은 당분간 학습과
  퀘스트 보상으로만 얻는다.
- 앱 어디에도 결제 버튼, 가격, 상품 카드, 유료 잠금, Premium·Plus 배지, 구독 안내,
  업셀 팝업, 외부 결제 링크, 결제를 암시하는 비활성 상점을 만들지 않는다.
- 나중에 쓸 예정이라는 이유로 빈 결제 자리나 가짜 상품을 먼저 노출하지 않는다. 존재만으로
  사용자는 학습 경험이 판매를 위한 미끼라고 느낄 수 있다.
- 결제는 충분한 무료 가치와 신뢰가 증명된 마지막 단계까지 보류한다.
- 결제를 논의하는 별도 단계에서는 사용자 감정, 학습 성취 뒤의 자연스러운 시점, 판매할
  실제 가치, 가격, 노출 빈도, 거부 후 경험, 환불·되돌리기를 먼저 정한다.
- 그 논의와 사용자의 명시적 승인 전에는 결제 연구를 했더라도 같은 작업에서 구현하지 않는다.
- 조급함, 손실 공포, 연속 팝업, 인위적 기능 제한으로 결제를 압박하지 않는다.

현재 측정할 것은 첫 퀘스트 완료율, 다음 날·7일 재방문율, 무료 보상 획득률과 장착률이다.
결제 전환율은 결제 기능을 도입하기로 결정한 뒤에만 지표로 추가한다.

## 출시 경계

- 현재 자동 출시 대상: GitHub Pages PWA
- 다음 단계: 계정·동기화·서버형 AI 기능의 비용과 개인정보 설계. 결제 UX는 계속 보류
- 이후 단계: Android 내부 테스트, iOS TestFlight, 양대 스토어 정식 출시

스토어 자동 배포는 서명, 결제, 개인정보, 심사, 단계 배포, 긴급 중단과 되돌리기 절차가
준비된 뒤에만 연다.

## 절대 조건

- 기존 브라우저 진도와 단어장 기록을 잃지 않는다.
- 공개 클라이언트에 API 키나 비밀정보를 넣지 않는다.
- 2,088개 오리지널 문제은행을 복제 기출문제로 바꾸지 않는다.
- Travel Mode를 전체 모의고사 안에 합치지 않는다.
- 로그인하지 않아도 핵심 학습 기능을 사용할 수 있다.
- 별도 수익화 논의와 사용자의 명시적 승인 전에는 어떤 결제 관련 UI도 추가하지 않는다.
