# 번역 합성 의미 평가 준비

상태: **실제 모델 평가 미실행**. 아래 검사는 fixture의 완전성과 평가 기준만 확인한다. 모델 호출, 외부 전송, 활성화, 배포를 수행하지 않는다.

- 입력과 판정 기준: `tests/fixtures/translation-semantic-evaluation.json`
- 오프라인 검사: `node --test tests/translation-semantic-fixtures.test.cjs`
- `npm test`에도 자동 포함된다. `test:quick`에는 별도로 추가하지 않았다.
- 일본어 8개, 영어 2개, 중국어 2개로 총 12개이다. 모두 새 합성 문장이다.

## 오프라인 검사 범위

정확한 선택 표현·문맥·언어·종류, 12개 번호, 입력 길이, 허용 의미와 명백한 실패, 네 가지 의미 대비, 기록 항목을 검증한다. 확장 문법 표현이 로컬 문법 사전의 정확한 별칭으로 처리되지 않는지도 확인한다. 배의 두 문맥은 입력 식별자가 다름을 확인할 뿐, 실제 캐시 분리의 통과 증거가 아니다.

테스트 통과를 번역 정확도 12/12 또는 실제 모델 성능으로 보고하지 않는다. 예시 번역은 의미 판정을 돕는 참고이며 정답의 완전한 목록이나 문자열 기반 자동 채점 규칙이 아니다. 구조와 목표 언어 문자 검사는 의미 검수를 대체할 수 없다.

## 별도 승인된 실제 평가 시

1. 실행 직전에 코드 커밋·실제 모델명·프롬프트 버전(없으면 관련 코드 커밋)을 기록한다. fixture의 모델명은 준비 당시 기준이지 실행 증거가 아니다.
2. 개인 단어장 대신 fixture 입력만 사용한다. 캐시나 학습 기록을 지우지 않고 분리된 평가 상태를 사용한다. 인증 토큰과 비밀값은 결과 파일에 기록하지 않는다.
3. 로컬 검수 사전에서 정확한 단어와 문맥이 일치하는지 먼저 확인한다. 특히 배와 쓰다는 사전 예문 일치 여부를 다시 확인한다. 로컬 경로가 선택되면 `authored` 또는 `grammar`로 기록하고 모델 호출로 세지 않는다. 입력을 바꿔 경로를 우회했다면 기존 케이스 결과로 표시하지 않는다.
4. 동의·검증·비용 통제를 유지한다. fixture는 전송 승인이 아니며 `learningTextApproved`나 Turnstile 토큰을 포함하지 않는다. 실제 CAPTCHA 해결이 필요하면 해당 승인 절차를 따른다.
5. 실제 반환 경로를 `grammar`, `authored`, `cache`, `mock`, `machine`으로 구분한다. Worker 요청 발생과 실제 추론 발생도 각각 기록한다. 요청만으로 추론을 증명할 수 없으면 추론 여부를 `unknown`으로 남기고 검증된 모델 성과에 포함하지 않는다.
6. 별도 결과 파일에 `caseId`, 정확한 `input`의 `term/context/target/kind`, `codeVersion`, `model`, `promptVersion`, `route`, `workerRequestOccurred`, `modelInferenceOccurred`, 결과 원문 `rawResponse`, `outcome`, 근거 `rationale`를 기록한다. 원본 fixture의 `evaluation`은 미실행 템플릿으로 유지한다.
7. 뜻·설명·생성 예문·예문 번역의 의미 일치를 사람이 검토한다. 다른 뜻이 참고로 포함되어도 현재 문맥의 주요 뜻을 대체해서는 안 된다. 7·8번 배는 같은 단어/언어지만 주요 뜻과 실제 캐시 경로가 구별되는지 확인한다.
8. `uncertain:true`와 거절은 `safe_incomplete`로 기록하며 정답으로 세지 않는다. 전체 12개 상태와 경로별 수를 공개하고, 검증된 실제 모델 시도에 대해 정답/시도·오답·안전한 미완료를 함께 보고한다. 응답 완료 건만의 정확도를 쓴다면 그 분모도 따로 명시한다.

준비·오프라인 검사·mock 회귀·실제 모델 평가·활성화·배포는 각각 별도 단계이다. 이 fixture나 오프라인 검사에는 네트워크 평가 실행기가 없다.
