# Listening pause re-synthesis: original-v10 single clip, 2026-11-20

Baseline: `main` e66d6d3 (v179). Pack `audio/listening/original-v10` (230 questions, 167
scripts, 428 clips). This note covers one re-synthesized clip only.

## Reported defect and measurement

- Question pair O09-II-L-41 / O09-II-L-42 shares
  `audio/listening/original-v10/F1/800786a0a81d1d16.mp3` (sha256
  `2c327d05b9f54bdf37f027fee0d5ae1da6c07b55233c4b1115abb2e6ed4ec494`, 443,288 bytes,
  55.3349 s, 44.1 kHz mono 64 kbps).
- `ffmpeg -af silencedetect=noise=-45dB:d=0.45` measured a 2.083-second low-level pause at
  40.492-42.575 s (`-50dB`: 40.492-42.562 s, 2.070 s). The same detector found 1.543, 1.588
  and 0.597-second pauses elsewhere in the clip.
- The pause is inside the media file. It is not produced by the playback transport.

## Why the pack seed could not stay

The build environment was rebuilt from the recorded pinned assets and matched them:

| Item | Recorded | Re-downloaded |
| --- | --- | --- |
| Model | `supertone-oss-archive/supertonic-3` revision `aafc6e32416a594460b32413efc49d7fe4ce6d46` | four ONNX files, `tts.json`, `unicode_indexer.json` SHA-256 all match `docs/qa/listening-audio-provisioning-v1.json` |
| Reference helper | `py/helper.py` SHA-256 `b14b1da8a018aa4db6ca8cbb927c32590bfc889b49116ea344c56e8351d94279` | identical |
| Voice presets | F1 `bbdec6ee…56dbc2`, M1 `e3560468…6b0a5b` | identical |
| Python deps | onnxruntime 1.23.1, numpy 2.3.5, soundfile 0.13.1 | installed at those versions in a build-only venv |

Re-synthesizing with the pack rule (`seedBase 20261015 + corpus row index 81 = 20261096`),
denoising steps 8, speed 1.0 and the recorded loudnorm/MP3 encoding returned the same media
length (55.3348846 s), the same byte count (443,288) and the same pause set, including the
2.083-second pause. The long pause is therefore a deterministic property of that seed's
sampling, not a text, chunking or encoding fault. Because it is deterministic, a re-run of the
same seed cannot remove it.

The published take therefore uses the neighbouring seed `20261097` with the same text, voice
preset, model revision, step count, speed and encoding chain. MP3 bytes are not expected to
match the old take: an identical decoder-side re-encode was also tried with FFmpeg 7.0.2 and
9.0.2 and neither reproduces the old container bytes.

## Result

- New file: sha256 `f0f02e7a667f907250f9b4fdcc75901c327bb7b98988c758bbb5d16f070e564e`,
  443,288 bytes, 55.3349 s (unchanged length and byte count).
- `ffmpeg silencedetect` at `-45dB:d=0.45`: pauses 1.542, 0.606, 1.430 and 1.441 s, longest
  1.542 s; no pause above 1.6 s. At `-50dB:d=0.45` the longest is 1.116 s. The 2.08-second
  pause is gone.
- A 60-clip spot check of the same pack measured a maximum internal pause of 1.684 s (median
  1.47 s), so the new take sits inside the pack's existing rhythm.
- Loudness/normalization after re-encoding: -18.53 LUFS integrated, -2.01 dBTP true peak,
  LRA 3.8 (previous take: -18.75 LUFS, -2.36 dBTP, LRA 4.0). Both are inside the verifier's
  accepted range.
- `scripts/verify-original-listening-audio.py` re-measured all 428 clips: 428 decoded, 0 missing,
  0 invalid, 0 unexpected, no duplicate hashes, no duration/rate warnings. Only the
  re-synthesized entry and the records hash changed in `manifest.json`; pack totals
  (37,791,896 bytes, 4,693.8084 s) are unchanged.

## Bookkeeping

- The replacement seed is recorded in `audio/listening/original-v10/seed-overrides.json` with
  its reason and the replaced SHA-256. `scripts/generate-original-listening-audio.py` reads that
  file, applies the override, validates that every override names a corpus row, and copies the
  list into `generation-records.json` as `seedOverrides` with `seedOverrideRule`. A fresh
  regeneration from the recorded assets therefore reproduces the published take rather than the
  replaced one.
- `manifest.json` was regenerated by the pack verifier, `data/original-listening-audio-v10.js`
  by `scripts/build-original-listening-catalog.mjs --pack original-v10`, and the release version
  was bumped so the new media is fetched instead of a cached file.

## Limits

- This is technical verification only. Nobody listened to the new take in this environment;
  `humanPronunciationReview`, `scriptToAudioMeaningVerified` and
  `physicalDevicePlaybackVerified` stay `false`. Pronunciation, spoken meaning, speaker
  distinction and device playback remain unverified, exactly as for the rest of the pack.
- The neighbouring seed changes the sampled noise of the whole clip, not only the pause
  region. Sentence-level wording and the voice preset are unchanged, but the take is a
  different recording of the same script.
- Actual listening review of both TOPIK II questions remains the gate for calling this
  resolved for learners.
